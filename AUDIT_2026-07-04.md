## 1. Gateway (Python) — 3 high, 13 medium, 13 low

### High

- **G-H1. Image alerts never receive `device_id`** — `api/app.py:875` calls `alert_evaluator.evaluate(event_id, None)` even though `originating_device_id` is in scope at line 866. Consequence: zone filtering skipped, device-scoped rules fire for every device, and `required_state` rules can never fire on the image path. The Phase 8/10 gating machinery is dead on the primary path; only the audio path (line 479) passes the device correctly. **One-line fix.**
- **G-H2. `POST /api/v1/tools/{tool_name}` executes all 46 tools with no auth** — `app.py:1336` has no `Depends(get_auth_context)`/`require_write`. Even with `CLAWCAM_AUTH_ENABLED=true`, an anonymous caller can invoke `capture_now`, `apply_config_patch`, `queue_firmware_update`, `create_alert_rule` (attacker-controlled `webhook_url`), etc. — bypassing both API-key auth and the `APPROVAL_REQUIRED_TOOLS` gate.
- **G-H3. Mock detectors wired into production profiles fabricate alerts** — `profiles/profiles.py:113` includes `mock_detector` in the wildlife chain; `inference/registry.py:110-116` maps `audio_birdnet`/`audio_glassbreak` to `MockDetector`; `audio/classifier.py:182` defaults to `MockAudioClassifier` (audio on by default, `config.py:55`). Mocks emit random `coyote`/`person`/`glass_break` hits at 0.5–1.0 confidence, persisted as real rows and evaluated by alert rules — a model-less gateway produces false predator/intrusion webhooks and pollutes analytics.

### Medium

- **G-M1. ~12 endpoints have no auth dependency at all** — incl. `GET /api/v1/commands/{device_id}/pending` (which also *mutates* status to delivered and returns queued config patches), `list_alert_rules` (leaks `webhook_url` secrets), zones, schedule-runs, state-transitions, audio/recent, cloud/uploads, firmware, metrics, tool-audit, dashboard. The `/ops` SPA collects an X-API-Key for endpoints that never check it.
- **G-M2. No cross-deployment ownership checks on writes** — zone/schedule/alert-rule update/delete/run guard only `require_write`; a key from deployment A can modify deployment B's resources. Also `data.get("deployment_id", auth.deployment_id)` lets non-admins plant resources in arbitrary deployments (`app.py:359, 568`).
- **G-M3. Tool dispatcher catches only `TypeError`** (`mcp_server/tool_dispatch.py:161`) — `ValueError` from arg coercion or `_validate_config_patch` escapes → HTTP 500 and the `_audit()` call is skipped, so failed calls vanish from the audit table.
- **G-M4. `upload_media` doesn't check the event exists** (`app.py:828`) unlike `upload_audio` — arbitrary files can be dropped as `media/<event_id>.jpg` for nonexistent events and run through inference/cloud sync.
- **G-M5. docker-compose won't boot** — `docker-compose.yml:15` pip-installs without `python-multipart`/`croniter`; pyproject's own comment says FastAPI raises at route registration without multipart.
- **G-M6. Extras don't match imports** — `[vision]` lacks `ultralytics` (detector.py imports it); `[audio]` lacks `birdnetlib`/`librosa`; `paho-mqtt`, `boto3`, `google-cloud-storage` undeclared anywhere.
- **G-M7. Dead config knobs** — `CLAWCAM_INFERENCE_WEIGHTS` and `scheduler_tick_interval_s` are read from env/config but never wired into the pipeline/engine (hardcoded 30 s tick).
- **G-M8. Heavy models reload on every image** — `registry.py:49` returns a fresh detector instance per event, defeating each detector's internal `_load()` cache (YOLO weights, easyocr reader re-load per upload).
- **G-M9. NULL `top_confidence` rows silently excluded** from every listing/analytics/CSV (`storage/database.py:724` `top_confidence >= ?` even at min_confidence=0).
- **G-M10. Mixed timestamp formats compared as strings** — SQLite `datetime('now')` (`YYYY-MM-DD HH:MM:SS`) vs `isoformat()` (`...T...+00:00`); since `' ' < 'T'`, boundary-day rows are misassigned in comparison windows (`clawcam_tools.py:499-503`, `app.py:1127`), API-key expiry checks (`auth_dependency.py:83`), and schedule window gates (`engine.py:149`).
- **G-M11. MCP schedule schema advertises 5 of 7 actions** — `stdio_server.py:472` enum omits `alert_digest` and `daily_summary`, which `scheduler/actions.py` supports.
- **G-M12. Firmware-bundle ingest inserts `deployment_id=None`** (`ingest/firmware_bundle.py:113` — key present with value None defeats `payload.get(..., "default")`), violating the NOT NULL column.
- **G-M13. Foreign keys never enforced at runtime** — `PRAGMA foreign_keys=ON` only runs inside `migrate()`'s connection; normal connections use SQLite's default (off), so orphan rows are accepted.

### Low

- G-L1. Capability gate fails open when a device declares no capabilities (`clawcam_tools.py:152, 280`).
- G-L2. Privacy masks applied *after* the unmasked JPEG is written, mask failure swallowed (`app.py:844-860`) — contradicts zones module docs.
- G-L3. Ops dashboard reads `avg_latency_ms` but the API emits `avg_duration_ms` — latency column permanently "—" (`ops_dashboard.py:148`).
- G-L4. `/api/v1/cloud/retry` inserts a new upload row instead of transitioning the failed one — failed counter grows monotonically.

- G-L7. Alert-rule creation duplicated between REST and MCP tool and drifting (webhook fallback, `required_state`/`severity` handling differ).
- G-L8. `models/` and `diagnostics/` are dead scaffold packages (one-line `__init__.py`).
- G-L9. `update_cloud_upload` unconditionally NULLs omitted optional columns (`database.py:870`).
- G-L10. Webhook SSRF guard resolves DNS separately from the request — DNS-rebinding TOCTOU (`alerts/webhook.py:63,109`).
- G-L11. `device_capabilities` "docstring" placed after code (not a docstring); fetch before existence check (`app.py:806`).
- G-L12. `add_event` media insert and `add_health` never populate their `deployment_id` columns — always `'default'`.
- G-L13. Scheduler `set_state` action skips `is_valid_state` validation — schedules can write arbitrary state strings (`engine.py:240`).

## 2. Firmware (ESP-IDF) — 5 high, 11 medium, 8 low

### High

- **F-H1. PIR wake pin collides with camera PCLK** — `main/main.c:59` hardcodes `CLAWCAM_PIR_GPIO 13`, which is the S3-EYE camera pixel-clock pin (`clawcam_camera.c:58 .pclk = 13`); the board profile explicitly says `"pir_gpio": -1` (no PIR on S3-EYE). EXT0 deep-sleep wake arms on a pin the camera drives → spurious wakes, corrupted motion semantics. Make PIR pin board-profile driven.
- **F-H2. MQTT success path never registers the device; gateway drops events from unknown devices** — registration only runs in the HTTP fallback (`main.c:212-254`); `mqtt_bridge/bridge.py:220` logs "unknown device; event dropped". On a fresh gateway, every MQTT event is silently discarded.
- **F-H3. `clawcam_mqtt_publish_event` returns ESP_OK on failure** (`clawcam_mqtt.c:189-207` — negative msg_id and PUBACK timeout both ignored) — main treats it as uploaded, skips HTTP fallback and registration.
- **F-H4. No Wi-Fi/netif/event-loop init anywhere** — the entire HTTP/MQTT/OTA upload stack is fully written but every network call fails unconditionally if upload is enabled. BUILD doc lists Wi-Fi as "Next port" but main.c presents upload as operative.
- **F-H5. SD save failure aborts the whole event path** — early `return` in `persist_capture` (`main.c:147-152`) skips event JSON and the entire upload block, contradicting its own log line ("event continues without SD artifact"). Full/absent SD card ⇒ captures vanish.

### Medium

- **F-M1.** Auth header sent as raw token (no `Bearer ` prefix), `api_token` hardcoded NULL, no Kconfig to set it; command client sends no auth at all — with gateway auth enabled, every firmware call gets 401/403.
- **F-M2.** No OTA partition table in `sdkconfig.defaults.esp32s3_eye` — `esp_ota_get_next_update_partition` fails on the default single-factory table.
- **F-M3.** OTA stub returns ESP_OK — node acks "OTA update applied; rebooting" without flashing anything; gateway marks the command executed.
- **F-M4.** Power/battery component stubbed (`battery_voltage = 0.0f; low_battery = false`) — low-battery protection is dead code; boards JSON says ADC channel -1 but main.c sets 0.
- **F-M5.** MQTT-received commands dropped: main passes NULL callback to `publish_event`, despite the header promising dispatch; node subscribes and waits 3 s for messages it discards.
- **F-M6.** Documented `CONFIG_CLAWCAM_MQTT_*` Kconfig symbols don't exist — broker URL defaults to `mqtt://localhost` (the device itself) and is unconfigurable via menuconfig.
- **F-M7.** Missing `REQUIRES driver`/`esp_timer` in camera/power/motion CMakeLists — will break IDF 5 builds.
- **F-M8.** Storage health fake (`free_bytes`/`used_bytes` never computed → `storage_free=0MB` always); `min_free_bytes`/`auto_cleanup_enabled` read by nothing — no disk-full policy (compounds F-H5).
- **F-M9.** Firmware never uploads image bytes — only event JSON with an sdcard path; `POST /api/v1/media/{event_id}` is the sole trigger for inference/alerts/cloud sync, so the gateway detection stack cannot operate from hardware captures.
- **F-M10.** Health reporting absent despite contract on both sides (gateway endpoint + MQTT subscription + sample payload exist; firmware never calls `publish_health` or POSTs health).
- **F-M11.** Commands larger than the firmware's 1024/4096-byte buffers are skipped client-side but already marked "delivered" by the gateway — permanently lost with no operator signal.

### Low

- F-L1. `clawcam_camera_release` on an uninitialized struct if capture fails pre-memset (latent UB, currently unreachable).
- F-L2. `vlen - 2` size_t underflow in `clawcam_config.c:171` on malformed patch strings → 62-byte garbage copy (the sibling parser in command_client guards this; config.c doesn't).
- F-L3. Unchecked `snprintf` truncation in command-client URL/ack builders.
- F-L4. Broker URI built as `"%s:%d"` — double port if URL already has one.
- F-L5. Every field capture carries `cls-…-smoke` classification IDs and `capture_profile:"smoke_test"` fallback — pollutes analytics.
- F-L6. Device registration timestamps hardcoded to `1970-01-01T00:00:00Z` even with valid RTC.
- F-L7. `clawcam_config.h` claims `ESP_ERR_INVALID_ARG` for unknown keys; implementation silently ignores them.
- F-L8. README lists a `clawcam_sensors` component that doesn't exist; omits 5 shipped components.

Positive check: wire formats line up almost perfectly — `{"data":...}` wrapper, endpoint paths, ack statuses, command payload keys, MQTT topic root, and firmware JSON validates against the schemas (`additionalProperties:false`).

Overall: the gateway code is well-organized with genuinely good instincts (parameterized SQL, SSRF/path-traversal guards, a real single-source-of-truth tool catalog, 845 green tests). The systemic weaknesses are (a) auth retrofitted onto only some endpoints while the most powerful surface is wide open, (b) scaffolding leaking into production — mock detectors in real profile chains, stubbed firmware components feeding live decision logic, unwired config knobs, and (c) early-phase docs that now actively contradict the code. The firmware is an honest scaffold with clean wire formats but is not field-ready: no Wi-Fi init, colliding PIR pin, and an MQTT path that mis-reports failure and loses events.
